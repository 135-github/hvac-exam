# R2：通风空调记录迁移只读试点

这是可选的、经本人核对后保存的 IndexedDB 副本，**不是正式学习存储切换**。现有三科 app.js 继续按原格式学习，R2 页面不写任一 localStorage 键，不从试点副本恢复覆盖原记录。

入口为各科“学习记录 → 记录迁移试点 · 通风空调”。R2 按既定分批顺序发布，R3 的逐次作答、commitAttempt、导入合并与导出 v3 未启用。不能把本版描述为全站已脱离数组下标。

## 存储与事务

数据库 `exam-memory` v1：attempts、sessions、snapshots、baseline、kv、meta、quarantine、revisions。attempts 建立 qid/at/session 索引但本批不写入日志。基线、会话、隔离记录均带 runId，永久 qid 为引用，当前题与显示题号独立。

保存前先分析并要求两项本人确认。一次 readwrite 事务写入原件快照、全部候选基线、会话、隔离原文及当前试点指针；只有 complete 才显示成功，abort 全部回滚。失败预览仍在，允许重试。

meta 中的 revision 在同一读写事务内比较，防止两个页面基于同一状态同时覆盖。BroadcastChannel 仅通知刷新。预览后原 localStorage 变化则要求重新核对；事务提交期间原站继续写入的极短竞争窗口不会丢失原数据，但试点可能是稍早的快照，保存后再次对比并提示过期。

撤回只恢复 activeRun 指针，所有已存副本保留；不删除数据库、不回写 localStorage。页面可以导出当前/历史试点与原件，导出格式明确为 `exam-memory-r2-pilot-export`，不会伪称可导入原站或 R3。

本批无日常新数据写入，故不增加每日定时快照；只在保存副本、撤回时建立真实检查点。不能声称恢复任意时点。后续启用新学习存储时再实现日常快照、清空前快照和导入前快照。

持久保存由用户按钮申请，返回结果如实显示；estimate 是来源级近似用量，包含同来源缓存/数据库，并不统计设备下载文件。

## 验证

`node tests/migration-r2.cjs` 需要现有 Playwright/Edge，覆盖：冻结内容一致、未确认零记录写入、三个旧存储键逐字节不变、草稿/撤销关联/隔离原文保留、配额异常导致事务全回滚、两个页面并发只能成功一个、撤回检查点、过期预览阻止、错科目阻止、真正断网核对与保存、手机布局及安全文字渲染。

这些测试使用独立浏览器中的合成数据。没有从用户浏览器读取真实记录。真实映射在用户使用页面时核对。

R3 才测试和启用真实 attemptId 幂等、30% 重叠合并、voidedAt 与显式恢复、主观题日志、复习调度重算。R2 的并发保存测试不是这些功能已完成的证明。
